# 냉장고한끼 V1.0 경쟁 앱 벤치마킹 및 Claude 개발 반영 지시서

## 0. 문서 목적

이 문서는 `냉장고한끼(fridge-meal)` V1.0 개발 시 참고할 경쟁 앱 벤치마킹 자료이다.

벤치마킹 대상은 공개 스토어 정보에서 확인된 유사 앱이다.

중요 원칙:

- 경쟁 앱의 UI/문구/디자인을 그대로 복제하지 않는다.
- 공개적으로 확인 가능한 기능과 사용자 흐름을 분석해 우리 앱에 맞게 재해석한다.
- `냉장고한끼`는 V1.0에서 서버, AI, OCR, 바코드 기능을 구현하지 않는다.
- 우리 앱의 핵심 차별점은 `빠른 냉장고 세팅 + 재료 관리 + 요리추천 + 장보기 연결`이다.

---

## 1. 벤치마킹 대상 요약

### 1.1 냉장고 털기 - AI 식재료 분석 · 레시피 추천

공개 Google Play 정보 기준 주요 기능:

```text
- 냉장고 사진 촬영 또는 갤러리 이미지 선택
- Google Gemini AI가 식재료 자동 분석
- 채소, 과일, 육류, 유제품, 음료, 조미료 등 카테고리 자동 분류
- 냉장고 속 재료 기반 메뉴 추천
```

이 앱은 `AI 이미지 분석` 중심이다.

우리 V1.0에서는 따라 하지 않는다.

이유:

```text
- 이미지 인식 정확도 이슈
- AI API 비용
- 개발 범위 증가
- MVP 검증 전에 복잡도가 높아짐
```

단, 추후 V2.x에서 참고할 수 있다.

---

### 1.2 냉장고 털기 : AI 재료관리, 레시피, 냉장고 파먹기

공개 Google Play / App Store 정보 기준 주요 기능:

```text
- 소비기한 임박 재료 우선 정리
- 같은 재료 자동 묶음
- 냉장 / 냉동 / 실온 위치별 분류
- 고기 / 채소 / 유제품 등 카테고리별 분류
- 장보기 체크 후 입고 버튼으로 냉장고 재고 등록
- 재료에서 레시피 검색
- 마음에 드는 레시피 저장
```

이 앱은 우리 V1.0과 가장 직접적으로 비교되는 앱이다.

특히 아래 기능은 적극 벤치마킹한다.

```text
- 소비기한 임박 재료 우선 표시
- 같은 재료 묶음
- 보관 위치별 필터
- 카테고리별 필터
- 장보기 완료 후 냉장고 입고 흐름
```

---

### 1.3 냉장고 파먹기 : 레시피, 냉장고 관리, 집밥, 냉파

공개 Google Play 정보 기준 주요 기능:

```text
- 보유 재료 등록
- 소비기한 임박 알림
- 보유 재료 기반 레시피 추천
- 복잡하지 않은 냉장고 관리
```

이 앱은 우리와 비슷하게 `단순한 재료 관리 + 레시피 추천`을 지향한다.

우리 앱은 여기에 `빠른 냉장고 세팅`과 `장보기 연동`을 더 강하게 가져간다.

---

### 1.4 냉쿡 : 유튜브 요리 레시피로 냉장고 털기

공개 App Store 정보 기준 주요 기능:

```text
- 입력한 재료 기반 YouTube 요리 영상 추천
- 필수 / 있는 / 없는 / 선택 / 대체 재료 분석
- 부족 재료 체크리스트
- 인기 요리 채널 추천
```

이 앱은 콘텐츠 방향이 `영상 레시피 추천`에 가깝다.

우리 V1.0에서는 YouTube 연동을 하지 않는다.

단, 아래 개념은 참고한다.

```text
- 가진 재료 / 부족 재료 명확한 구분
- 대체 재료 개념은 추후 V1.2 이후 고려
```

## 2. 경쟁 앱에서 배울 점

## 2.1 소비기한 임박 재료 우선 표시

경쟁 앱들은 소비기한 임박 재료를 핵심 가치로 강조한다.

우리 앱에도 반드시 반영한다.

### 냉장고한끼 적용 방향

홈 상단에 `오늘 먼저 써야 할 재료` 섹션을 둔다.

```text
오늘 먼저 써야 할 재료

두부 D-1
대파 D-2
콩나물 D-2
```

냉장고 목록 기본 정렬은 `유통기한 임박순`이다.

---

## 2.2 같은 재료 자동 묶음

경쟁 앱 중 일부는 같은 재료를 자동으로 묶어 보여준다.

이 기능은 재료가 많아질수록 중요하다.

### 냉장고한끼 적용 방향

V1.0에서는 완전한 자동 병합까지는 필수 구현하지 않아도 된다.

다만 DB와 UI는 같은 재료 묶음을 확장할 수 있게 설계한다.

#### V1.0 최소 구현

```text
같은 이름의 재료가 중복 등록되면 경고 또는 병합 제안
```

예:

```text
이미 '두부'가 냉장고에 있어요.
기존 재료를 수정할까요, 새로 추가할까요?
```

#### V1.1 확장

```text
두부
총 2개 항목

- 두부 / 냉장 / D-1 / 조금 남음
- 두부 / 냉장 / D-5 / 충분함
```

---

## 2.3 보관 위치별 필터

경쟁 앱은 냉장 / 냉동 / 실온 분류를 강조한다.

우리 앱도 V1.0 필수 기능으로 반영한다.

### 냉장고한끼 필터

```text
전체
냉장
냉동
실온
양념/소스
기타
```

### 내부 코드

```text
all
refrigerated
frozen
room_temp
sauce
etc
```

---

## 2.4 카테고리별 필터

경쟁 앱은 고기, 채소, 유제품처럼 카테고리별 분류를 제공한다.

우리 앱도 식재료 카테고리를 관리하되, V1.0에서는 너무 복잡하게 하지 않는다.

### V1.0 추천 카테고리

```text
단백질
채소
과일
곡류/면
유제품
양념/소스
가공식품
음료
기타
```

### 주의

보관 위치와 카테고리는 다르다.

예:

```text
두부
보관 위치: 냉장
카테고리: 단백질
```

```text
고추장
보관 위치: 양념/소스 또는 실온
카테고리: 양념/소스
```

## 2.5 장보기 → 입고 흐름

경쟁 앱에서 가장 좋은 포인트는 `장보기 체크 후 입고` 흐름이다.

이 기능은 냉장고 관리 앱에서 매우 중요하다.

사용자가 장보기 목록을 체크한 뒤, 다시 냉장고에 재료를 등록해야 한다면 이탈 가능성이 높다.

### 냉장고한끼 적용 방향

장보기 항목을 체크하면 팝업을 띄운다.

```text
두부를 냉장고에 추가할까요?

보관 위치: 냉장
남은 정도: 충분함
유통기한: 선택 입력

[냉장고에 추가]
[나중에]
```

### 구현 규칙

- 장보기 항목을 체크하면 `is_checked = true`
- 사용자가 `냉장고에 추가`를 누르면 `fridge_items`에 신규 등록
- source_type은 `shopping`
- 냉장고에 추가된 장보기 항목은 `입고 완료` 상태로 표시할 수 있게 확장 가능

## 2.6 재료에서 레시피 검색

경쟁 앱은 재료를 보다가 레시피를 바로 검색하는 흐름을 제공한다.

우리 앱에서는 `요리추천` 탭이 별도로 있지만, 냉장고 식재료 카드에서도 연결하면 좋다.

### 냉장고한끼 V1.0 적용

식재료 카드에 보조 액션을 둔다.

```text
[이 재료로 요리 보기]
```

누르면 해당 재료가 포함된 레시피 목록으로 이동한다.

V1.0에서 시간이 부족하면 이 기능은 후순위로 둔다.

## 3. 경쟁 앱 대비 냉장고한끼 차별화 전략

## 3.1 가장 큰 차별점: 빠른 냉장고 세팅

경쟁 앱들은 재료 등록을 강조하지만, 사용자는 처음에 재료를 하나하나 등록하는 것을 귀찮아한다.

냉장고한끼는 최초 진입장벽을 낮추기 위해 `냉장고 빠른 세팅`을 핵심 기능으로 둔다.

### 빠른 세팅 흐름

```text
식생활 유형 선택
→ 기본 식재료 세트 자동 로드
→ 있는 재료만 체크
→ 빠진 재료 추가
→ 냉장고 생성
```

### V1.0 기본 프리셋

```text
집밥 기본형
간단 자취형
아이 있는 집
다이어트/건강식
```

이 기능은 경쟁 앱보다 더 강하게 가져가야 한다.

---

## 3.2 레시피 추천은 AI보다 룰 기반

경쟁 앱 중 일부는 AI 분석을 강조한다.

우리 앱 V1.0에서는 AI를 넣지 않는다.

대신 사용자가 이해하기 쉬운 룰 기반 추천을 제공한다.

### 분류

```text
바로 가능
조금만 사면 가능
임박 재료로 가능
```

### 장점

```text
추천 이유가 명확함
비용 없음
오프라인/로컬 구현 가능
개발 범위가 안정적임
```

---

## 3.3 장보기 목록은 냉장고와 강하게 연결

단순 체크리스트가 아니라, 장보기 완료 후 냉장고 재고로 이어져야 한다.

경쟁 앱의 장점을 참고하되 우리 앱에서는 더 명확한 사용자 흐름으로 설계한다.

```text
부족 재료 장보기 추가
→ 구매 완료 체크
→ 냉장고에 추가
→ 재고 업데이트
```

## 5. DB 보완 지시

기존 DB에 아래 구조 또는 필드를 고려한다.

---

## 5.1 fridge_items 중복 처리 고려

기존:

```sql
CREATE TABLE fridge_items (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  ingredient_name TEXT NOT NULL,
  category TEXT,
  storage_type TEXT NOT NULL,
  stock_level TEXT NOT NULL,
  expire_date TEXT,
  memo TEXT,
  source_type TEXT NOT NULL DEFAULT 'manual',
  is_active INTEGER DEFAULT 1,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
```

추가 고려 필드:

```sql
normalized_name TEXT
```

`normalized_name`은 중복 감지에 사용한다.

예:

```text
대파
대 파
파
```

V1.0에서는 단순 trim/lowercase 수준으로 처리해도 된다.

---

## 5.2 shopping_items 입고 여부 확장

기존:

```sql
CREATE TABLE shopping_items (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  ingredient_name TEXT NOT NULL,
  category TEXT,
  source_type TEXT NOT NULL DEFAULT 'manual',
  source_ref_id INTEGER,
  is_checked INTEGER DEFAULT 0,
  created_at TEXT NOT NULL,
  updated_at TEXT NOT NULL
);
```

추가 고려 필드:

```sql
is_added_to_fridge INTEGER DEFAULT 0
added_to_fridge_at TEXT
```

이 필드는 장보기 완료 후 냉장고에 반영되었는지 구분하는 데 사용한다.
