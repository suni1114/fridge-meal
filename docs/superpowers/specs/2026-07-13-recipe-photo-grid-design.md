# 요리추천 사진 그리드 개편 — 설계

날짜: 2026-07-13
브랜치: `feat/ingredient-based-recipes`

## 배경

요리추천 목록은 현재 세로 1열의 가로형 카드다. 카드마다 작은 카테고리 이모지 타일, 냉장고 매칭 상태, 부족 재료 칩, 상세보기 버튼이 들어간다. `recipes.json`의 200개 요리에는 **사진이 하나도 없다**(`image` 필드 전무). 각 요리는 만개의레시피 추천순 검색 페이지를 가리키는 `recommendUrl`만 갖고 있다.

목표는 사진 중심의 2열 그리드로 바꾸고, 각 요리에 만개의레시피 추천순 **1등 레시피의 사진**을 붙이는 것이다.

## 결정 사항

- **사진은 다운로드해서 앱에 번들한다.** CDN 핫링크(가능함을 확인)가 아니라 로컬 에셋으로 포함한다. 오프라인에서도 보이고 외부 서버에 의존하지 않는다.
- **최대한 작게 압축한다.** 정사각 360px, WebP 화질 60. 원본 썸네일이 장당 약 29KB이므로 장당 8~15KB, 200장 합계 2~3MB를 목표로 한다.
- **사진은 나중에 교체한다.** 파일명을 `<menuId>.webp`로 고정해, 같은 이름으로 덮어쓰면 코드 수정 없이 교체되게 한다.
- 카드에는 냉장고 매칭 상태를 **사진 좌상단 작은 배지**로 남긴다. 앱의 핵심 가치인 매칭 정보를 목록에서 잃지 않기 위함이다.

## 구성 요소

### 1. 수집 스크립트 (`scratchpad/fetchRecipeImages.cjs`, 일회성)

각 요리의 `recommendUrl`(만개의레시피 추천순 검색)을 열어 첫 번째 결과의 썸네일 주소와 레시피 ID를 뽑고, 이미지를 받아 `sharp`로 재인코딩한다.

- 출력 사진: `assets/recipes/<menuId>.webp` (360×360, WebP q60)
- 출력 매핑: `src/data/recipeImages.ts` — menuId → `require()` 정적 매핑
- 출처 기록: `docs/seed/recipe-image-sources.json` — menuId, 요리명, 만개의레시피 레시피 ID, 원본 사진 주소. 나중에 사진을 교체·검증할 때 쓴다.
- 서버 부하를 피해 순차 요청하며 요청 간 간격을 둔다. 실패 건은 재시도 1회 후 건너뛰고 로그로 남긴다.

`sharp`는 devDependency이며 앱 번들에는 들어가지 않는다.

### 2. 사진 참조 (`src/data/recipeImages.ts`, 자동 생성)

React Native의 `require()`는 정적 문자열만 받으므로, 스크립트가 200줄짜리 매핑 파일을 생성한다. `recipeImage(menuId)`가 `ImageSourcePropType | undefined`를 돌려주고, 사진이 없는 요리는 기존처럼 카테고리 이모지로 대체된다.

### 3. 요리추천 목록 (`src/screens/RecipeListScreen.tsx`)

기존 `RecipeCard`(가로형)를 2열 그리드 카드로 교체한다.

- 정사각 사진(1:1), 사진 좌상단에 매칭 상태 배지("바로 가능" / "재료 2개" / "메인 부족")
- 임박 재료를 쓰는 요리는 불꽃 배지
- 사진 아래 요리명(최대 2줄)
- 탭 5개(전체/국·찌개/반찬/메인/간편)와 검색 결과 모두 같은 그리드를 쓴다

부족 재료 목록과 장보기 담기는 상세 화면에서 확인한다.

### 4. 레시피 상세 (`src/screens/RecipeDetailScreen.tsx`)

이미 요구 구성(대표 사진 → 요리명 → 메인/서브/양념 → 만개의레시피·유튜브 버튼)을 갖추고 있다. 바뀌는 것은 상단 대표 사진이 원격 URL이 아닌 번들된 로컬 사진을 쓰는 것뿐이다. 하단 "부족한 재료 장보기 담기"는 유지한다.

## 검증

- `npx tsc --noEmit`
- 웹 빌드
- `localhost:8081`에서 목록 → 상세 → 외부 링크(만개의레시피/유튜브) 클릭 확인
- 수집 성공 건수와 총 용량을 보고한다
